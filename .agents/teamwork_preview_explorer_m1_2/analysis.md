# Investigation Analysis: Milestone 1 - Org Restructure

## Observation
1. The project requires replacing the existing default agents in `src/store/agentStore.ts` with three new core agents: SUM, SATIN, and SINCARE.
2. The project requires converting a set of "Shared Skills & Rules" into granular `Skill` objects.
3. Agents must be linked to these Skills via `skill_ids`. 
4. The database uses UUIDs for `skill.id`. We must insert the skills first, capture their generated UUIDs, and map those to the agents' `skill_ids` during insertion.
5. The `initialize` function in `src/store/agentStore.ts` currently has its auto-seeding logic commented out. We need to restore it with logic that only triggers when both `skills` and `agents` tables are empty for the user.
6. A migration script (`scripts/reseed_org.ts`) is requested to delete existing agents and skills, triggering the `initialize` re-seed upon the next application load.

## Code Constraints
- `agents.skill_ids` in PostgreSQL is of type `JSONB` and stores an array of UUIDs.
- `skills.id` is automatically generated by `uuid_generate_v4()`.
- Both `agents` and `skills` tables enforce Row Level Security (RLS) on `user_id`. Thus, inserts via the client in `initialize()` correctly capture `user.id`.
- The node script `scripts/reseed_org.ts` will bypass RLS by using the `SUPABASE_SERVICE_ROLE_KEY` if available, or it will require a specific `USER_ID` to perform the cleanup.

## Fix Strategy

### 1. Update `src/store/agentStore.ts`
- **Define `defaultSkills`**: Create a constant array of the 8 granular skills (Ask Context, Planning, Documentation, Communication, Review, Delegation, Consistency, Memory) based on the user's raw data. Include a temporary string `id` (e.g., 'ask-context') for internal mapping.
- **Redefine `defaultAgents`**: Replace the old default agents with SUM, SATIN, and SINCARE. Assign their `skill_ids` using the temporary string IDs from `defaultSkills`.
- **Implement Seeding Logic**: In the `initialize` method, add a check: `if (skills.length === 0 && agentsData.length === 0)`.
- Inside the check:
  1. Insert `defaultSkills` into the `skills` table.
  2. Create a mapping of the inserted UUIDs back to the temporary string IDs.
  3. Map the string `skill_ids` on `defaultAgents` to their new UUID equivalents.
  4. Insert `defaultAgents` into the `agents` table.

### 2. Create `scripts/reseed_org.ts`
- Write a Node.js script utilizing `@supabase/supabase-js`.
- It should authenticate via `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`.
- It should take a `USER_ID` as a command-line argument.
- It will execute `delete()` on both `agents` and `skills` tables for the specified `USER_ID`.
- This ensures the database is clean, allowing the updated `initialize()` function to seed the new structure correctly on the next page load.
