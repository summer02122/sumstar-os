# Analysis: SumStar OS Org Restructure (Milestone 1)

## Core Findings

1. **Current State in `agentStore.ts`:**
   - There is a `defaultAgents` array (CEO Agent, Research Agent, etc.) that is currently obsolete and unused.
   - The `initialize` function fetches `skills` and `agents` but explicitly states `// Removed auto-seeding logic so deleted agents don't respawn.`.
   - `Agent` creation requires `skill_ids` which are standard Supabase IDs (UUIDs or serials).

2. **Skill Definitions Needed:**
   - Based on the user's "Shared Skills & Rules", we need to extract modular skills.
   - Required skills based on agent mapping: `ask-context`, `planning`, `delegation`, `review` (or `quality-control`), `communication`, `documentation`, `consistency`, and `memory` (for SINCARE's note-taking requirement).

3. **Agent Definitions Needed:**
   - **SUM**: CEO (ORCHESTRATOR) — requires `ask-context`, `planning`, `delegation`, `review`, `communication`.
   - **SATIN**: HR & Agent Architect (ARCHITECTURE) — requires `documentation`, `communication`, `review` (quality-control).
   - **SINCARE**: Executive Secretary (SECRETARY) — requires `documentation`, `planning`, `memory`, `communication`.

4. **Re-seeding Logic:**
   - `initialize` must be updated to detect a completely empty organization (no skills and no agents) and perform a one-time seed.
   - Since `skill_ids` are generated by the database upon insertion, the seeding logic must:
     1. Insert the default skills.
     2. Retrieve their DB-generated IDs.
     3. Map the string keys (e.g., `'ask-context'`) to the DB IDs.
     4. Replace the string keys in the default agents' `skill_ids` with the actual DB IDs.
     5. Insert the default agents.

5. **Migration Script (`scripts/reseed_org.ts`):**
   - Needs to connect to Supabase and delete existing rows in `skills` and `agents`.
   - Because Supabase RLS is likely enabled, running a Node script requires either a `SERVICE_ROLE_KEY` or authenticating with a user's email/password. 
   - The most reliable way for a local tool is to initialize with `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` to bypass RLS, delete the records, and optionally insert the new ones directly (or leave it to `agentStore.ts` upon next app load). Given the prompt says "trigger the re-seeding", deleting the records will successfully "trigger" the `initialize` function's re-seeding logic when the user refreshes the page. Alternatively, the script can import the seeding logic and do it directly if the `user_id` is known.

## Proposed Strategy

1. **Define Constants**: Create `DEFAULT_SKILLS` and `DEFAULT_AGENTS` in `agentStore.ts` with temporary `key` fields for mapping.
2. **Update `initialize()`**: Add conditional logic that checks if both `skillsData` and `agentsData` are empty. If so, execute the 5-step seeding process described above.
3. **Create `reseed_org.ts`**: Write a TypeScript node script using `@supabase/supabase-js` that connects to the DB, wipes `agents` and `skills`, and instructs the user to refresh the app to trigger the new initialization sequence.
